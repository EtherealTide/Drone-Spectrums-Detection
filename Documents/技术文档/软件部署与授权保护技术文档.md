## 1. 概述

本系统在完成功能开发后，需要以二进制形式部署到目标工作站，并实施以下保护措施：

| 保护目标 | 实现方案 |
|---------|---------|
| 源代码保护 | Nuitka 将 Python 编译为原生机器码（C → 二进制） |
| 模型文件保护 | Fernet 对称加密，密钥嵌入编译后二进制 |
| 使用授权控制 | HMAC-SHA256 签名许可证 + 硬件指纹绑定 |
| 跨 GPU 兼容 | 运行时自动在目标 GPU 上导出 TensorRT 引擎 |

## 2. 许可证授权系统

### 2.1 设计目标

- 将软件使用权限绑定到特定硬件（不可转移）
- 支持设定有效期，到期后拒绝启动
- 许可证文件本身可防篡改（数字签名保护）
- 无需网络连接，离线验证

### 2.2 机器指纹生成

机器指纹通过读取两项硬件标识符并哈希合并生成，实现代码位于 `license_manager.py`：

```python
def get_machine_id() -> str:
    cpu = subprocess.check_output(
        ['powershell', '-NoProfile', '-Command',
         '(Get-CimInstance Win32_Processor).ProcessorId'],
    ).decode().strip()

    disk = subprocess.check_output(
        ['powershell', '-NoProfile', '-Command',
         '(Get-CimInstance Win32_DiskDrive)[0].SerialNumber'],
    ).decode().strip()

    raw = (cpu + disk).encode()
    return hashlib.sha256(raw).hexdigest()[:32].upper()
```

**组成要素：**

| 来源 | WMI 类 | 属性 | 说明 |
|------|--------|------|------|
| CPU | `Win32_Processor` | `ProcessorId` | CPU 制造商写入的唯一序列号 |
| 硬盘 | `Win32_DiskDrive` | `SerialNumber` | 存储设备序列号 |

**合并方式：** 将两个字符串拼接后取 SHA-256 哈希值的前 32 位十六进制大写表示，作为 32 字符机器指纹。

> **注意：** 使用 PowerShell 的 `Get-CimInstance`（而非已废弃的 `wmic` 命令），确保在双击启动和命令行启动两种场景下行为一致。

### 2.3 许可证生成原理（授权方）

授权方持有私有 HMAC 密钥，通过 `generate_license.py` 为指定机器生成许可证：

```
输入：machine_id（机器指纹）、expiry（有效期 YYYY-MM-DD）
         ↓
步骤1：构造 JSON Payload
  payload = {"machine_id": "ABCD1234...", "expiry": "2026-12-31"}
         ↓
步骤2：HMAC-SHA256 签名
  sig = HMAC(key=_HMAC_KEY, msg=payload, digestmod=SHA256).hexdigest()
         ↓
步骤3：打包并 Base64 编码
  data = {"payload": payload_str, "sig": sig}
  license_content = Base64Encode(JSON(data))
         ↓
输出：license.lic 文件（单行 Base64 字符串）
```

其中 `_HMAC_KEY` 由固定密码短语（Passphrase）经 SHA-256 派生：

```python
_HMAC_PASSPHRASE = b"DroneDetect_LICENSE_KEY_BUAA_2026_..."
_HMAC_KEY = hashlib.sha256(_HMAC_PASSPHRASE).digest()   # 32 字节
```

### 2.4 许可证验证原理（被授权方）

程序启动时在 `main.py` 的 `_check_license()` 方法中调用 `license_manager.verify_license()`，验证逻辑如下：

```
读取 license.lic（Base64 解码 → JSON 解析）
         ↓
步骤1：签名完整性校验
  expected_sig = HMAC(_HMAC_KEY, payload_str) 
  若 expected_sig ≠ sig → 拒绝（文件被篡改）
         ↓
步骤2：硬件绑定校验
  machine_id = get_machine_id()
  若 machine_id ≠ payload["machine_id"] → 拒绝（硬件不匹配）
         ↓
步骤3：有效期校验
  若 date.today() > payload["expiry"] → 拒绝（已过期）
         ↓
全部通过 → 允许启动
```

验证失败时程序通过 PyQt6 弹出错误对话框，显示拒绝原因及本机指纹码，然后调用 `sys.exit(1)` 退出。

### 2.5 完整授权流程

```
┌─────────────────────────────────────────────────────────────────┐
│  被授权方（用户）                    授权方（开发者）            │
│                                                                 │
│  1. 首次运行 exe                                                │
│     → 弹窗显示机器指纹码             2. 收到指纹码              │
│                                                                 │
│  3. 将指纹码发送给授权方  ─────────────────────────────────►   │
│                                       运行 generate_license.py  │
│                                       输入指纹码 + 有效期       │
│                                       生成 license_XXXXXXXX.lic │
│                                                                 │
│  5. 收到 license.lic      ◄─────────  4. 发送 license.lic      │
│     放入 exe 同目录                                              │
│                                                                 │
│  6. 重新运行 exe                                                │
│     → 验证通过，正常启动                                         │
└─────────────────────────────────────────────────────────────────┘
```

### 2.6 安全性分析

| 攻击方式 | 防御机制 |
|---------|---------|
| 伪造许可证文件 | HMAC-SHA256 签名校验，无私钥无法伪造 |
| 将许可证复制到其他机器 | 硬件指纹绑定，机器码不匹配则拒绝 |
| 修改系统日期绕过有效期 | 系统时间可被篡改，此处为设计取舍（离线系统的固有局限） |
| 提取 HMAC 密钥 | Nuitka 编译后密钥嵌入机器码，无 Python 字节码可逆向 |
| 暴力破解指纹 | SHA-256 输出 32 字符（128 bit），暴力破解不可行 |

## 3. 模型文件加密保护

### 3.1 TensorRT 引擎 GPU 强绑定问题

YOLO 推理引擎使用 TensorRT 进行加速。TensorRT 在导出 `.engine` 文件时会针对当前 GPU 进行深度硬件优化，导致：

- 同一 `.engine` 文件**无法跨不同型号 GPU 使用**
- 不同 TensorRT 版本生成的 engine **格式不兼容**
- 优化过程依赖当前 GPU 的计算能力（Compute Capability）、显存大小等参数

因此，不能将预先生成的 `.engine` 文件打包进分发包用于所有目标机器。

**解决方案：** 分发加密的 PyTorch 源模型（`.pt.enc`），在目标机器**首次运行时**自动解密并针对当前 GPU 导出 TensorRT 引擎。

### 3.2 加密方案设计

采用 **Fernet 对称加密**（基于 AES-128-CBC + HMAC-SHA256，由 Python `cryptography` 库提供）：

```
开发阶段（授权方）：
  best.pt ──encrypt_model_tool.py──► best.pt.enc
                  │
                  └── 使用 _PASSPHRASE 派生的 Fernet 密钥

分发包内容：
  best.pt.enc（加密文件）+ DroneDetection.exe（含嵌入密钥）
```

密钥派生方式（`model_crypto.py`）：

```python
_PASSPHRASE = b"DroneDetect_MODEL_KEY_BUAA_2026_..."
_FERNET_KEY = base64.urlsafe_b64encode(hashlib.sha256(_PASSPHRASE).digest())
```

SHA-256 将任意长度 Passphrase 压缩为 32 字节，经 URL-safe Base64 编码后满足 Fernet 密钥格式要求（44 字符）。

### 3.3 首次运行自动转换流程

`main.py` 中 `_prepare_model()` 方法在子进程启动前执行，完整流程如下：

```
启动时检查
     │
     ├─ best.engine 存在？ ──是──► 直接跳过（快速路径）
     │
     └─ 否，best.pt.enc 存在？ ──否──► 抛出 FileNotFoundError
                │
                是
                ▼
        显示等待对话框
   "正在为当前 GPU 生成 TensorRT 引擎..."
                │
        后台线程执行：
        ensure_engine_ready()
                │
        1. Fernet 解密 best.pt.enc → 内存
        2. 写入系统临时目录 drone_model_XXXX.pt
        3. ultralytics YOLO.export(format="engine", ...)
        4. 移动生成的 .engine 到 exe 目录
        5. 删除临时 .pt 文件
                │
                ▼
        关闭等待对话框 → 正常继续启动
```

**线程设计：** 转换过程在独立 `threading.Thread` 中执行，主线程持续调用 `QApplication.processEvents()` 保持 UI 响应，避免 Windows 显示"无响应"提示。

### 3.4 导出参数说明

TensorRT 引擎导出时的关键参数：

```python
model.export(
    format="engine",   # 导出格式：TensorRT
    imgsz=512,         # 推理图像尺寸，需与训练时一致
    dynamic=True,      # 启用动态 batch，支持 1~N 任意批量
    batch=16,          # 最大批量大小（对应 max_batch_windows=16）
    half=True,         # FP16 半精度，提升推理速度约 2 倍
    device=0,          # 使用第 0 号 GPU
)
```

| 参数 | 值 | 说明 |
|------|-----|------|
| `dynamic` | `True` | 必须启用。本系统窗口数量动态变化（1~16），固定 batch 会在窗口数不足时报错 |
| `batch` | `16` | 对应 `max_batch_windows` 配置，告知 TensorRT 最大并发推理图像数 |
| `half` | `True` | FP16 精度，RTX 系列显卡 Tensor Core 对 FP16 有硬件加速 |

## 4. Nuitka 编译打包

### 4.1 技术选型与原理

Python 代码保护方案对比：

| 工具 | 保护原理 | 保护强度 | PyTorch 兼容性 |
|------|---------|---------|--------------|
| PyInstaller | 打包为自解压 `.pyc` 字节码 | 弱（可被 uncompyle6 反编译） | 好 |
| **Nuitka** | 编译为 C 代码再编译为机器码 | **强（无字节码）** | 较好 |
| cx_Freeze | 打包 `.pyc` 字节码 | 弱 | 一般 |

**Nuitka 工作原理：**

```
Python 源码 (.py)
       │
       ▼  Nuitka Python-level 优化
中间表示 (AST + IR)
       │
       ▼  Nuitka C 代码生成器
C 源代码 (.c)
       │
       ▼  MSVC / MinGW 编译
原生机器码 (.exe + .pyd + .dll)
```

最终产物中不含任何 `.py` 或 `.pyc` 文件，逆向难度大幅提升。

### 4.2 编译参数详解

完整编译命令（在 `Software/` 目录下执行）：

```bat
python -m nuitka ^
    --standalone ^
    --enable-plugin=pyqt6 ^
    --module-parameter=torch-disable-jit=yes ^
    --include-package=ultralytics ^
    --include-package=torch ^
    --include-package=torchvision ^
    --include-package=cv2 ^
    --include-package=cryptography ^
    --include-package=PyQt6 ^
    --include-package-data=ultralytics ^
    --include-data-files=class_names.txt=class_names.txt ^
    --nofollow-import-to=polars ^
    --nofollow-import-to=IPython ^
    --nofollow-import-to=notebook ^
    --nofollow-import-to=pytest ^
    --nofollow-import-to=setuptools ^
    --include-data-dir=UI=UI ^
    --windows-console-mode=attach ^
    --lto=no ^
    --jobs=8 ^
    --output-filename=DroneDetection ^
    --output-dir=..\dist ^
    main.py
```

**各参数说明：**

| 参数 | 类别 | 说明 |
|------|------|------|
| `--standalone` | 输出模式 | 生成独立目录，包含所有运行时依赖，目标机器无需安装 Python |
| `--enable-plugin=pyqt6` | 插件 | 启用 PyQt6 插件，自动处理 Qt 插件目录（platforms、styles 等）的包含 |
| `--module-parameter=torch-disable-jit=yes` | 参数 | 禁用 TorchScript JIT，避免打包时编译不必要的 JIT 相关代码 |
| `--include-package=ultralytics` | 包含包 | 强制包含整个 ultralytics 包（含所有子模块），因其使用大量动态导入 |
| `--include-package=torch` | 包含包 | 强制包含整个 PyTorch 包 |
| `--include-package=cryptography` | 包含包 | 包含 cryptography 库（用于模型解密） |
| `--include-package-data=ultralytics` | 数据文件 | 包含 ultralytics 包内的非 Python 文件（`cfg/default.yaml` 等配置文件） |
| `--include-data-files=class_names.txt=class_names.txt` | 数据文件 | 将类别名称文件复制到输出目录根路径 |
| `--include-data-dir=UI=UI` | 数据文件 | 将 `UI/` 子包目录整体复制到输出目录（包含 UI 资源文件） |
| `--nofollow-import-to=polars` | 排除 | 不跟踪 polars 的导入（ultralytics 可选依赖，本系统不使用，避免引入 IPython） |
| `--nofollow-import-to=IPython` | 排除 | 排除 IPython（开发工具，生产环境无需） |
| `--nofollow-import-to=pytest` | 排除 | 排除测试框架 |
| `--lto=no` | 编译优化 | 关闭链接时优化（LTO），大幅减少编译时间，对运行性能影响极小 |
| `--jobs=8` | 并行 | 并行 C 编译线程数，建议设为 CPU 核心数 |
| `--output-filename=DroneDetection` | 输出 | 可执行文件名称 |
| `--output-dir=..\dist` | 输出 | 输出目录 |

### 4.3 多进程 Spawn 模式的特殊处理

本系统使用 `multiprocessing` 启动两个子进程（接收进程、推理进程），且设置为 `spawn` 启动模式：

```python
mp.set_start_method("spawn", force=True)
```

在 `spawn` 模式下，每个子进程通过**重新执行可执行文件本身**来初始化，而非 fork 父进程。打包后子进程会重新启动 `.exe` 并传入特殊参数，因此 `if __name__ == "__main__":` 入口块的第一行**必须**调用 `freeze_support()`：

```python
if __name__ == "__main__":
    mp.freeze_support()   # 捕获子进程启动信号，避免死循环
    main()
```

若缺少此调用，打包后每个子进程启动时会再次进入 `main()` 逻辑，导致进程数指数级膨胀（无限递归创建子进程）。

### 4.4 分发包结构

Nuitka 编译完成后，`dist/DroneDetection.dist/` 的结构：

```
DroneDetection.dist/
├── DroneDetection.exe          ← 主程序入口
├── best.pt.enc                 ← 加密模型（手动添加）
├── class_names.txt             ← 类别名称（已由 --include-data-files 自动包含）
├── command.json                ← 通信协议定义（手动添加或 --include-data-files）
├── license.lic                 ← 许可证（单独为每台机器生成发放）
│
├── ultralytics/                ← ultralytics 包（含 cfg/default.yaml 等数据文件）
├── torch/                      ← PyTorch 包（含 CUDA kernel DLL，约 4~6 GB）
├── PyQt6/                      ← Qt6 运行时
│   └── Qt6/plugins/            ← Qt 插件（platforms、styles、tls 等）
│
├── *.pyd                       ← 各 Python 模块编译后的动态库
├── python312.dll               ← Python 运行时
└── *.dll                       ← CUDA、TensorRT、OpenCV 等依赖库
```

> **体积说明：** 完整分发包约 10~15 GB，主要来自 PyTorch CUDA 运行时（含所有计算能力的 CUDA kernel）。压缩为 `.7z` 格式后通常缩减至 3~5 GB。

## 6. 关键模块文件说明

| 文件 | 用途 | 是否随软件分发 |
|------|------|:------------:|
| `license_manager.py` | 机器指纹生成、许可证验证 | ✅ |
| `model_crypto.py` | 模型加密解密、TRT 引擎自动生成 | ✅ |
| `generate_license.py` | 授权方许可证生成工具 | ❌ 仅开发者持有 |
| `encrypt_model_tool.py` | 授权方模型加密工具 | ❌ 仅开发者持有 |
| `best.pt` | 原始 PyTorch 模型权重 | ❌ 保密，不分发 |
| `best.pt.enc` | Fernet 加密的模型权重 | ✅ 随分发包提供 |
| `best.engine` | TensorRT 引擎（GPU 专属） | ❌ 不预置，目标机自动生成 |
| `license.lic` | 目标机器的使用许可证 | ✅ 单独为每台机器发放 |
| `command.json` | 下位机通信协议定义 | ✅ |
| `class_names.txt` | YOLO 检测类别名称 | ✅ |
